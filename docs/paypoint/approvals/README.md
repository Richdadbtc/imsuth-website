## Approval rules

- A typed name alone is not documentary evidence.
- Each approval requires the approver's name, title, decision, date and signature or a linked immutable approval record such as a signed PDF, approved meeting minute, controlled ticket or digitally signed document.
- Email approval is acceptable only when retained in the project decision register with sender, date, full decision text and message identifier.
- Conditional approvals must list every condition, owner and due date. An unmet condition keeps the relevant gate incomplete.
- Absence of a response is not approval.
- The Project Delivery Lead verifies completeness but cannot approve on behalf of IMSUTH management, Finance, Privacy, Security or the hosting provider.
- No document in this package authorizes use of real patient/payment data, provider integration, staging or production deployment, DNS/TLS/cPanel changes, or modification of the public website.

## Status vocabulary

- **PENDING:** no sufficient evidence has been attached.
- **APPROVED:** the accountable approver accepted the decision and evidence meets the stated criteria.
- **APPROVED WITH CONDITIONS:** documentary approval exists, but every stated condition must be tracked; the gate closes only if the relevant acceptance criteria permit it.
- **REJECTED:** the approver declined the decision; reasons and next action must be recorded.
- **NOT APPLICABLE:** allowed only with written justification and approval from the accountable owner.
